# 路线图

这个路线图来自原始想法、MVP 实现过程中的取舍，以及目前暴露出的体验问题。

## 近期优先级

- 更精细的 gaze 延迟校准：不同机器、摄像头和 GazeFollower 滤波策略会产生不同延迟，需要可配置或自动估计。
- 更透明的证据展示：在最终笔记旁显示“哪些页被提交、哪些片段被判定为重点、证据强度如何”。
- 更好的 GazeFollower 启动体验：预热模型、明确进度、处理校准窗口前置失败。
- 阅读页命中可视化：生成笔记前允许用户看到本次视线关注热区，帮助判断是否可信。
- 错误恢复：摄像头占用、校准失败、AI provider 失败时给出更明确的用户操作。

## 文档与阅读能力

- 扫描版 PDF OCR：当前主要适合文字型 PDF；扫描版需要 OCR 并保留文字框坐标。
- 图片/公式/表格标记：无法直接识别的区域应标注为图片、表格或公式，再交给 AI。
- 页码映射增强：AI 使用的原文页码可能和阅读页不同，需要更稳定的阅读页到原文片段映射。
- 长文分节：支持按章节或阅读片段分批生成，再合并成全局笔记。

## 用户体验

- 托盘/悬浮窗形态：按需打开，减少阅读前的折腾感。
- 阅读模式选择：沉浸式只看、主动选中辅助、轻量提醒等模式可选。
- 走神提醒：需要谨慎，不应打断有价值的思考。可先做低频、可关闭、只在长时间无有效 gaze 时提示。
- 笔记风格画像：通过引导、设置和用户反馈构建偏好，而不是一次性问卷。
- 复盘交互：用户核对笔记后可标记“准确/误判/遗漏”，用于改进下一次提示词和阈值。

## 隐私与安全

- 明确本地数据管理界面：查看、导出、删除会话。
- API 提交前预览：让用户看到将提交哪些页和哪些证据。
- 本地模型选项：探索无需外部 API 的笔记生成。
- 权限最小化：摄像头只在阅读采样阶段开启，生成和核对阶段关闭。

## 开源共建

- 代码审阅与工程化：欢迎有经验的开发者帮助梳理架构、边界和测试。
- 低门槛任务：把可复现 bug、文档修订、阈值调参、UI 文案、测试样例拆成适合新贡献者的小 issue。
- 拆分可插拔模块：视线追踪、OCR、AI provider、笔记模板。
- 增加贡献指南和 issue 模板。
- 补充跨平台测试：Windows、macOS、Linux。
- 许可证评估：当前 GazeFollower 依赖适合非商业阶段；若未来需要更宽松使用范围，需要重新评估。
