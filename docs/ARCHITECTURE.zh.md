# 架构说明

## 数据流

1. 用户上传文档。
2. 后端保存源文件和快速元信息。
3. 阅读器按页展示原文档页面。
4. 前端记录当前页文字框在屏幕上的实际坐标。
5. GazeFollower 进程采样 gaze 坐标和时间戳。
6. 后端根据页码时间线、布局变更、gaze 样本和文字框计算注意力摘要。
7. 生成笔记时只选择本次稳定阅读过的页。
8. 后端构造内部 AI 上下文，调用配置的 AI provider 或本地规则版。
9. 前端只展示最终用户笔记。

## 关键约束

- 阅读器禁止滚动，避免滚动导致 gaze 坐标无法映射到原位置。
- 缩放和翻页后必须重新提交屏幕文字框。
- 缩放/翻页附近的 gaze 样本会被忽略，降低延迟误判。
- 连续快速翻页不算已读。
- 原文全文只是上下文；主动选中、标注和用户需求是强证据，gaze 停留是弱信号，需要保守解释。

## 目录职责

- `app/main.py`：API 路由、会话创建、gaze 启停、笔记生成入口。
- `app/gaze_worker.py`：独立进程运行 GazeFollower，避免阻塞 Web 服务。
- `app/document_renderer.py`：PDF 页面渲染、裁白边、文字框提取。
- `app/attention.py`：将 gaze 样本与页面文字框重合，计算关注时长。
- `app/note_generator.py`：构造 AI 上下文和 prompt，调用 provider。
- `static/app.js`：前端状态、阅读页渲染、布局提交、结果展示。
